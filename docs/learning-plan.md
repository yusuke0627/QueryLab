# QueryLab 学習計画

## 到達目標

QueryLabは、Go（Golang）・MyGoとクエリビルダのアルゴリズムを学ぶ開発プロジェクトです。
成果物は実装、テスト、設計文書、レビュアー向け資料を含みます。
自分で処理を追い、設計の理由と制約を説明し、小さな変更と検証ができる状態を目指します。
資料やコードの生成、テスト成功だけを学習の達成とは扱いません。

## 段階ごとの学習テーマ

| 段階 | Go / MyGoで学ぶこと | アルゴリズム・設計で学ぶこと | レビュー時の理解確認 |
| --- | --- | --- | --- |
| M1 SELECTコア | 構造体、独自型、スライス、ポインタ、ジェネリクス、エラー、JSON、標準ツール | 式ツリー、再帰走査、検証と生成の分離、SQLと引数の生成 | 小さな式からSQLと引数を手で導き、実装と照合する |
| M2 SQLite実行・スキーマ | `database/sql`、interface、`context`、`defer`、リソース管理 | 実行とコンパイルの境界、結果列と行値のモデル、スキーマ探索 | キャンセルとRows解放の流れ、NULLの保持方法を説明する |
| M3 JOIN・リレーション | モデル拡張、パッケージ境界、テストデータの設計 | 名前解決、結合条件、外部キーのグラフ、複合キー、行の多重度 | LEFT JOINのNULL側や1対多の結果を予測し、曖昧な経路を説明する |
| M4 MyGo GUI | MyGoの実際のAPI、イベント処理、状態管理、Goとの接続 | GUI状態とQuery Modelの同期、保存形式、非同期実行 | 一つの編集がモデル・プレビュー・結果に伝わる経路を追う |
| M5 限定的双方向編集 | `go/parser`とAST、診断情報、対応構文の検査 | 構文解析、正規化、意味の等価性、revisionと同期ループ | 対応外構文を拒否する理由と、取り込み後の意味の維持を説明する |

MyGoの依存先・APIはM4の技術検証で確認します。現時点でGUIを実装済みとは扱いません。
機能の順序と受け入れ条件は[実装計画](implementation-plan.md)を参照してください。

## 進め方

1. 着手前に、今回学ぶ概念と説明できるようになりたいことを決める。
2. 最小の入力例、期待結果、境界条件を紙上または資料で整理する。
3. 実装してテストする。設計上の選択と代替案を記録する。
4. レビュー資料にコードの入口、処理の流れ、検証根拠、制約をまとめる。
5. レビュアーの質問や小さな変更課題に取り組み、理解の不足を振り返る。

学習のための比較実装や実験を行う場合は、仮説・比較条件・結果を資料に残します。
測定していない速度やメモリ使用量を、実測結果として書かないことにします。

## M1の演習

- `And(Eq(Col("active"), Bool(true)), IsNull(Col("deleted_at")))`をツリーとして描き、SQLと引数を予測する。
- LIMITの未指定と0を区別する理由、`Ptr`が返す値の寿命を説明する。
- 構造体の代入後もスライスやポインタの参照先が共有される例を挙げる。
- 引数の追加位置を変えたとき、SQLの`?`と値の対応がどう壊れるか説明する。
- 許可する比較演算子を増やすなら、検証・SQL・Go生成・テスト・文書の変更箇所を列挙する。
- 再帰的に文字列を作る実装で、ツリーの深さがコピー量にどう影響するか説明する。

演習は理解確認用であり、実装済み機能や実施済みの学習成果を示すものではありません。
