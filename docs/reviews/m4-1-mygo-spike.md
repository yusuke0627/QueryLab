# M4-1 MyGoの最小GUIを動かす技術検証

## 状態と範囲

MyGo v0.10.0で、Goのみで書くネイティブUIの最小画面を実装しました。
ウィンドウのビルドと起動処理、画面なしの操作テストを確認しました。
実画面の取得時にMacがロックされていたため、見た目・日本語入力の確認は未完です。
DB接続、スキーマ一覧、JOIN編集、SQL/Goの取り込み、保存機能は今回含みません。

## 読み順

1. [preview.go](../../desktop/preview.go): 入力の文字列を持つDraftと、SQLの意味を持つSelectを区別する。
2. 同ファイルのbuildQuery → generatePreview: 入力検査とモデルへの変換、既存生成器の呼び出しを追う。
3. [main.go](../../desktop/main.go): appに保存する入力値と、viewが作る画面部品の違いを確認する。
4. [テスト](../../desktop/preview_test.go): チェック・文字入力・生成・エラーと復元の手順を追う。

## 依存と選定の判断

MyGoの公式実装は[github.com/egoist/mygo](https://github.com/egoist/mygo)です。
Goコードで画面を作る[ネイティブUI](https://mygo.run/docs/ui)とWebフロントエンドの方式があります。
今回は、まずGoと既存のQuery Modelの学習に集中するため前者を選びました。
MyGoの画面部品はそのview呼び出し中だけ有効なので、永続状態として保存しません。

- GUIモジュール: MyGo v0.10.0、Go 1.27.3。
- クエリ本体: Go 1.23を維持。rootのgo.modとgo.sumは変更していません。
- GUIのgo.modから相対パスで本体を参照します。rootにgo.workは追加しません。
- 版の根拠は[MyGo v0.10.0のgo.mod](https://proxy.golang.org/github.com/egoist/mygo/@v/v0.10.0.mod)と固定版のui/doc.goを確認しました。
- MyGoのSQLiteプラグインは導入しません。後続でDBをつなぐ際も既存の読み取り専用実行層を利用します。

ルートへMyGoを直接追加する案では、本体の最低Goと依存がUIに引っ張られます。
UIを独立モジュールにすると検証コマンドは二組になりますが、本体だけの利用・検証は継続できます。
HTMLの別画面を作る案より、まずGoの入力値・関数・メソッドだけを追える構成を優先しました。

## 入力からプレビューまで

画面のDraft → buildQuery → Select → Compile / Generate → Previewという流れです。
画面部品を生成器へ渡すことも、SQLプレビューのためにDBを開くこともありません。
ここでは「画面の見せ方を変える」と「SQL生成を検証する」を独立して行えるようにしています。

テーブル名と列名は識別子として引用します。SQLの式を文字列として解析する入力欄ではありません。
取得列はカンマ区切りで、名前にカンマのある列、別名や修飾列の編集はこの最小画面の対象外です。
activeとdeleted_atの条件は学習用のサンプルで、実在する列かどうかは検証しません。
件数は空欄なら未指定、0なら0行、負数や整数でない入力はエラーです。

入力を変更しただけでは再生成せず、「以下は前回の生成結果」と表示します。
生成を押して失敗した場合、以前の成功結果は消してエラーを表示します。サンプル復元で再生成できます。
SQL・引数・Goコードは表示のみで、直接編集や逆変換はできません。

生成は現在の小さな入力でのみUIスレッド上で行います。大きなクエリやDBのI/Oをこの処理へ追加せず、
後続で非同期処理・キャンセル・古い結果を反映しない仕組みを設計します。
入力長に対する文字列分割と変換に加えて既存生成器の処理を行います。画面描画や性能は未測定です。

## 再現と検証

リポジトリのルートから:

```sh
cd desktop
GOWORK=off CGO_ENABLED=0 go test ./... -count=1
GOWORK=off CGO_ENABLED=0 go vet ./...
GOWORK=off go tool mygo vet .
GOWORK=off go tool mygo dev
```

確認済み:

- クエリ本体はGo 1.23.12で全体テストと静的チェックが成功。GUIは別モジュールなので、このテストには含まれません。
- Go 1.27.3 / macOS arm64でGUIのテストと静的チェック、MyGoのvetが成功。
- テストはSQLと引数、Go生成、引用符と0件、入力エラー、チェックの切替、
  文字入力、古い結果の表示、エラー後のサンプル復元を確認。
- CGO_ENABLED=0でネイティブアプリをビルドし、CLIで開発用.appを作成・起動するところまで確認。
- doctorはmacOSの基本環境を確認。iOS/AndroidのSDKや配布署名は今回の対象外。

未確認:

- Macロックのため、実画面の見た目・スクロール・日本語IME・選択コピー・リサイズ。
- Windows/Linuxでの実行、正式なアプリ配布、コード署名。

実画面の確認は別途、ロック解除後に上記devコマンドで行ってください。
特に長いSQLとGoコードが読めるか、日本語の入力が保たれるかを確認します。
