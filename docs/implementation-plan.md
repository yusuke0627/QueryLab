# 実装計画

## M1: SELECTコア — 初期実装済み

- [x] Goモジュール、開発ルール、設計文書、実行例。
- [x] 共通Query Modelと宣言的コンストラクタ。
- [x] SELECT、DISTINCT、別名、比較、論理式、NULL判定、並べ替え、ページング。
- [x] 構造検証とSQLite向けSQL / 引数の生成。
- [x] Model → Go生成、整形と実際のコンパイルによるモデル等価性の確認。
- [x] SQL・引数順序、JSONの型維持、不正モデル、深さ制限、SQL実動作のテスト。

受け入れ条件: `go test ./...`と`go vet ./...`が成功し、`go run ./examples/select`でSQL・引数・Goを確認できること。
SQL実動作テストは`sqlite3`が必要。CI導入時には必須ジョブで用意します。

## M2: SQLite実行・スキーマ — 次の着手先

1. SQLiteドライバを比較し、CGO・配布・保守・対応Goバージョンを設計判断に記録する。
2. `database/sql`を受ける実行アダプターを追加する。接続の所有者とClose責務を定義する。
3. 読み取り専用接続、キャンセル、タイムアウト、行数上限を実装する。
4. 結果列、値型、NULL、同名列を保持する結果モデルを追加する。
5. スキーマ、列、主キー、外部キー、索引を取得する。

受け入れ条件: 一時SQLite DBに対する実ドライバのテストで、SELECT、NULL、空結果、エラー、
キャンセル、リソース解放、スキーマ情報を確認する。コンパイラはDBなしで利用できること。

## M3: JOIN・リレーション

1. JOINモデル、INNER / LEFT、ON、修飾列の名前解決を追加する。
2. SQL/Go生成とモデル保存をJOINに対応させる。
3. 外部キー由来のリレーション候補を作り、ユーザーの選択からJOINを構築する。
4. 複合キー、自己参照、曖昧な経路、LEFT JOINのNULL側を扱う。
5. 平坦な結果を維持したうえで、1対1・1対多のマッピングを設計する。

受け入れ条件: 実DBを使ったJOIN結果とGo生成の等価性を確認する。
同名列・別名・複合キー・行重複を失わず、曖昧なリレーションを自動選択しないこと。

## M4: MyGo GUI

1. MyGoの依存先とAPIを確認し、最小画面の技術検証を行う。
2. バージョン付き保存DocumentとGUIメタデータを定義する。
3. DB接続とスキーマ表示、列・条件・並べ替え・件数の編集を実装する。
4. JOIN/リレーションの選択を視覚的に編集できるようにする。
5. ModelからSQL/Goプレビュー、実行、結果表を接続する。
6. 保存・読込とエラー表示を整える。

受け入れ条件: GUIで作ったSELECT/JOINを実行し、同じモデルからSQLとGoを取得できること。
DB操作と生成器がGUI実装から独立してテストできること。

## M5: 限定的双方向編集

1. SQLとGoそれぞれの対応構文・非対応構文・正規化規約を文書化する。
2. SQL → Modelのパーサーと診断、パラメータ保持を実装する。
3. Go → Modelを許可したASTに限定して実装する。
4. MyGoへ編集元・revision・診断を含む同期制御を追加する。
5. 対応外入力では最後の正常モデルを維持する。

受け入れ条件: 対応構文でModel → SQL/Go → Modelの意味的等価性を確認する。
未対応構文、壊れた入力、同期ループ、更新競合でモデルが失われないこと。
任意のGoコードを実行しないこと。

## 初期範囲の後に検討する機能

GROUP BY / HAVING、集約、IN / BETWEEN、サブクエリ、CTE、UNION、BLOB、
EXPLAIN QUERY PLAN、型付き結果構造体の生成、変更系SQL。
これらの優先度はSELECT・実行・JOIN・MyGo・双方向編集を保ったまま決めます。
