# レビュアー向けガイド

## レビューの目的

QueryLabはGo・MyGoとクエリビルダのアルゴリズムを学ぶプロジェクトです。
機能の正しさ、設計の説明、検証の根拠、学習者の理解を確認します。
資料に書かれた説明と、学習者が自分の言葉で説明できることは分けて評価してください。

## 読む順序

1. [README](../README.md)で現在の対応範囲と動かし方を確認する。
2. [学習計画](learning-plan.md)で段階ごとの学習目標を確認する。
3. 対象段階のレビュー資料から、コードとテストをたどる。
4. [設計文書](design.md)で判断理由と今後の接続先を確認する。
5. [実装計画](implementation-plan.md)で今回の範囲と後続作業を分ける。

## 共通の確認観点

- 対象と非対応の入力が明確で、対応外を黙って落としていないか。
- 学習目標が具体的で、実装・設計判断・テストと結びついているか。
- データ構造、アルゴリズム、状態の所有者を説明できるか。
- 正しさを支える不変条件と、その条件を確かめるテストがあるか。
- 採用案の理由と代替案のトレードオフを説明できるか。
- 計算量の分析、性能測定、推測、将来計画が区別されているか。
- 再現手順があり、実施結果・スキップ・未検証事項が明確か。
- 制約を説明し、未知の小さな変更にも理由を持って対応できるか。

## 各レビュー資料に含める内容

対象範囲と学習目標、コードを読む順序、設計判断と代替案、入力から出力までの処理例、
不変条件、必要な計算量の分析、再現コマンドと期待結果、テストとの対応、制約、
理解確認の質問を含めます。性能測定をする場合は環境と測定方法も記載します。

実装変更時は資料の更新も成果物に含めます。
レビュー指摘への対応時は、何を変え、どの根拠で確認したかを該当資料に反映します。
